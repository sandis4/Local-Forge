# Local Forge — чат и дообучение локальных моделей

Rust-приложение с интерфейсом в стиле **Material 3 (Material You)** — той же
дизайн-системы, что на Pixel и в MUI. Обучение выполняет Python-движок
(`python/`): приложение запускает его, показывает живой прогресс и шлёт команды
(пауза/сохранение/стоп/профиль).

```bash
local-forge run        # или просто двойной клик по local-forge.exe
```

Сборка `--release` — оконное приложение: двойной клик открывает окно без
чёрной консоли. Рабочая папка берётся из `--project`, иначе — текущая, а если
в ней нет `models/` и `database/` (двойной клик), то корень проекта рядом с exe.

Python ищется как `python.exe` по PATH (полный путь, не голая строка «python»:
в корне проекта лежит пустой файл `python`, и Windows находил его первым).
Переопределить можно через `--python` или файл `python.txt` рядом с exe
(одна строка с путём к `python.exe`).

## Экраны

Слева — навигация в стиле M3: логотип, «Новый чат», **Чат** (главный экран),
**Хаб моделей**, **Обучение**, **Настройки**, разделы «Проекты» и «Недавние»,
карточка пользователя. Светлая тема по умолчанию, тёмная — переключателем.

Python-процессы (чат-движок, llama.cpp, Hugging Face) запускаются с
`CREATE_NO_WINDOW` — никаких консольных окон. Загрузка показывается
индикатором в интерфейсе.

### Чат

- Модели из `models/` (safetensors) и `models_gguf/` (GGUF). GGUF идёт через
  **llama.cpp** (`llama_bin/llama-server.exe`): mmap-загрузка, KV-кэш между
  репликами, потоковая выдача — это самый быстрый путь на CPU. Q4 предлагается
  первым. Если сборка llama.cpp умеет `-fa`, flash attention включается сам
  (при отказе сервер перезапускается без него); потоки ограничены физическими
  ядрами — SMT греет ноутбук, почти не ускоряя шаг.
- **Модель может быть больше свободной RAM**: веса грузятся через mmap
  (`--load-mode mmap`, `--fit off`), страницы подтягиваются с диска по мере
  надобности — работать будет, но медленнее. Если llama.cpp всё же не смог
  выделить память, контекст автоматически уменьшается вдвое и ставится
  меньший batch; в статусе видно, что происходит.
- **Разбитый GGUF** (`имя-00001-of-00003.gguf`) показывается одной моделью:
  в список попадает первый шард, остальные llama.cpp подхватывает сам.
- Если файл неполный или несовместимый, чат пишет это прямо: «нет нужных
  тензоров, перекачай модель целиком», а не общее «не хватает памяти».
- LoRA-адаптер из любой папки `output*/`: подключается к базовой модели.
  Для safetensors-моделей используется transformers + `model_loader`
  (mmap/offload, чтобы не упасть по RAM).
- Параметры запуска (раскрывающийся блок): контекст, **тип KV-кэша**
  (f16 / q8_0 / q4_0), потоки, максимум токенов, temperature.
- Потоковая выдача, кнопка «Стоп» и счётчик токенов в секунду.
- Без модели на safetensors чат тоже работает — просто выбери GGUF.

### Публичный API через Radmin VPN

В «Параметрах» чата включи **«Открыть доступ к текущей модели»**. API
поднимется автоматически после загрузки модели и будет доступен по адресу
`http://<IP>:<порт>/v1`, где IP по умолчанию берётся у адаптера Radmin VPN
(поле «IP» можно заполнить вручную; пусто = авто).

- ключ — всегда `1`: `Authorization: Bearer 1` (или `X-API-Key: 1`);
- модель — `current-activated`;
- клиенту отдаётся только имя загруженной модели в system-промпте, личность
  и настройки Local Forge наружу не уходят;
- поддержаны `GET /v1/models`, `POST /v1/chat/completions`, `stream: true`
  (SSE), CORS.

Пример:

```bash
curl http://26.0.0.5:8000/v1/models -H "Authorization: Bearer 1"

curl http://26.0.0.5:8000/v1/chat/completions \
  -H "Authorization: Bearer 1" -H "Content-Type: application/json" \
  -d '{"model":"current-activated","messages":[{"role":"user","content":"Привет"}],"max_tokens":128}'
```

С Python OpenAI SDK:

```python
from openai import OpenAI
client = OpenAI(base_url="http://26.0.0.5:8000/v1", api_key="1")
print(client.chat.completions.create(
    model="current-activated",
    messages=[{"role": "user", "content": "Привет"}],
).choices[0].message.content)
```

API живёт, пока открыт Local Forge и загружена модель; запросы к одной модели
выполняются последовательно. Ключ `1` и отсутствие HTTPS — только для
доверенной сети Radmin: не пробрасывай порт в интернет и разреши порт
в брандмауэре Windows для Radmin VPN.

### Проекты

В левом меню раздел **Проекты**: кнопка **+** открывает системный выбор папки
(без консольного окна). Проект сразу становится активным, а его путь —
папкой для агента. Повторный клик по строке переключает активный проект,
крестик убирает его из списка (файлы на диске не трогаются). Список и активный
проект сохраняются в настройках.

### Режимы чата: Агент, Think, Web

Агент — не отдельная вкладка, а переключатель под композером: тот же чат,
но модель может выполнять действия. Рядом — Think и Web.

- **Агент** — модель читает и правит файлы папки проекта, запускает команды и
  продолжает, пока задача не сделана. Инструменты: `list_dir`, `read_file`,
  `write_file`, `append_file`, `replace_in_file`, `run_command`, а с Web —
  `web_search` и `web_fetch`; все файловые пути ограничены папкой проекта.
  Ход работы показывается блоком прямо в ленте чата. Папка задаётся в кнопке
  «Параметры» в шапке чата (по умолчанию — рабочая).
- **Think** — если chat template модели умеет `enable_thinking`, включается
  родной reasoning. Если родного режима нет (например, Gemma/Forge GGUF),
  Local Forge просит модель оформить рассуждение в `<think>...</think>` и сам
  разделяет поток: рассуждение уходит в свёрнутый блок, после `</think>` —
  финальный ответ. Без включённого Think модель может рассуждать прямо в ответе.
- **Web** — поиск перед ответом **и чтение страниц**: верхние ссылки
  открываются, из HTML вытаскивается читаемый текст и вставляется в контекст
  (сниппеты остаются только подсказкой). В агенте модель может сама вызывать
  `web_fetch` для любой ссылки и читать страницу целиком, а не только описание.
  Движки: **DuckDuckGo, Bing, Google, Яндекс** (выбор рядом с переключателем).
  Google и Яндекс без API часто отдают капчу — тогда приложение честно пишет
  об этом и показывает результаты Bing/DuckDuckGo. Никаких ключей и аккаунтов
  не нужно; локальные/приватные адреса для `web_fetch` запрещены.
- **Таймаутов нет**: HTTP-запрос к модели и `run_command` (до 15 минут) ждут
  столько, сколько нужно. Долгая запись файла не обрывается.
- Режимы сохраняются в `%APPDATA%\LocalForge\settings.json` и переживают
  перезапуск; `--tab agent` открывает чат с уже включённым агентом.

### Хаб моделей

Лента **Discover** собирается из трёх секций, и в ней остаются **только GGUF** —
такие модели реально скачиваются списком файлов и запускаются в чате:

1. **Свежие релизы автора** — до трёх последних GGUF с Hugging Face. Автор
   задаётся в настройках (по умолчанию `YoSaNoo`), рядом с ником — синяя
   галочка, чтобы было видно, что это тот самый аккаунт.
2. **Кванты** — переключается в настройках:
   - «Под железо» (по умолчанию) — свежие GGUF от Unsloth; приложение читает
     размеры шардов (`-00001-of-000NN`), складывает их в реальный вес кванта
     и берёт лучший по качеству, который влезает в бюджет. Бюджет считается по
     свободной RAM и числу потоков CPU (примерно 1.25 ГБ на поток), в шапке
     видно `RAM свободно / всего` и `CPU`.
   - «Unsloth» — просто три последних GGUF-репозитория Unsloth.
3. **Популярное на Hugging Face** — по скачиваниям, тоже только GGUF.

- Шапка хаба закреплена: прокручиваются отдельно список слева и карточка
  справа, поэтому заголовок, поиск и переключатели не уезжают, а файл/README
  не наезжают друг на друга.
- Строка результата: логотип, имя (полное — во всплывающей подсказке), автор
  с галочкой, квант и вес, лайки/скачивания и давность обновления. Новые
  релизы помечены точкой.
- Карточка справа: имя, автор с галочкой, цветные теги, метаданные
  (обновлено, создано, лайки, скачивания, библиотека) и выбор **кванта**, как
  в Unsloth: шарды `-00001-of-000NN` склеены в один вариант (`UD-IQ1_S`,
  `Q4_K_M`, `BF16`…), у каждого показан суммарный вес. «Скачать» тянет все
  шарды выбранного кванта; для репозиториев без GGUF остаётся выбор файла.
- README рендерится как markdown: заголовки, списки, ссылки, код — ссылки
  открываются в браузере.
- Список файлов теперь включает `.gguf` (раньше расширение терялось, и
  скачивание отвечало «нет подходящих файлов»). Скачивание сплит-квантов
  проверено на репозитории с тремя шардами.

### Обучение

Слева — полная настройка, справа — **«Предпросмотр запуска»**: модель, датасет,
метод, LoRA r, контекст, batch/accum, LR, оптимизатор, оборудование, свободная
RAM и статус проверки. Внизу — «Проверить» и «Начать обучение».

1. **Настройки — полный конфиг обучения.** Модель, датасет, валидация,
   identity, папка сохранения; эпохи, LR, grad norm, warmup, контекст,
   сэмплы, batch, grad accumulation, шаг сохранения; LoRA r/alpha/LoRA+,
   режим lora/full; профиль нагрузки, оптимизатор, dtype, AMP и AMP dtype,
   gradient checkpointing, QLoRA, LISA; length grouping / packing / кэш;
   дистилляция KD (soft-targets учителя); репетиция, KL-якорь, SFT/ORPO;
   экспертные флаги (attn, Liger, compile, доп. аргументы). Пустое поле =
   «пусть решает автоплан main.py». Значения при старте подставляются из
   автоплана под твоё железо.
2. **Своя команда.** Сверху можно вставить строку вида
   `python main.py --model models/gemma_base --epochs 2 --packing` — флаги
   разберутся и заполнят форму (поддерживаются родные имена main.py,
   а также `--data`/`--out`). Незнакомые флаги уходят в «доп. аргументы»,
   после применения сразу запускается проверка под железо. Автоплан при этом
   не перетирает введённые значения.
3. **Обучение** — шаг/всего, прогресс-бар, ETA, карточки loss / LR / RAM /
   потоки / профиль, журнал, панель управления снизу.
4. **Готово** — итог, путь к адаптерам, кнопки «Открыть папку» и «Ещё раз».

Тема переключается между тёмной и светлой кнопкой в шапке.

## Ускорение на CPU: что взято из colibri

colibri — C-движок для **MoE-моделей**: эксперты лежат на VRAM/RAM/диске,
роутер решает, откуда читать, есть prefetch и int4. Для плотной Gemma через
transformers это не применимо напрямую. Что перенесено по смыслу:

- **GGUF + mmap через llama.cpp** — тяжёлая модель считается на CPU из
  отображённого в память файла, без загрузки всех весов в RAM;
- **KV-кэш между репликами** — llama-server не перечитывает историю;
- **потоковая выдача** и остановка на полуслове;
- **выбор квантизации** — Q4 вместо F16 там, где важна скорость;
- для safetensors — mmap/offload из `model_loader` (тот же принцип «не держать
  всё в RAM»).

Не перенесено: тиринг экспертов по устройствам, роутинг, MTP-спекудяция —
это части конкретных MoE-движков, а не универсальные ручки.

## Проверка перед запуском

Перед обучением приложение запускает `python/forge_plan.py` — тот же код
железа и планирования, что у тренера (`hardware.py`, `memory_plan.py`),
и сверяет с ним каждую настройку:

- **пути**: модель и `*.safetensors`, токенизатор, датасет (первая строка JSON),
  папка сохранения, ORPO-файл;
- **память**: веса vs RAM/VRAM, оценка активаций по контексту и batch,
  размер логитов (словарь × токены), режим disk-stream;
- **контекст**: не больше `max_position_embeddings` модели, сравнение
  с рекомендацией автоплана;
- **точность**: bf16 на CPU (AVX512-BF16), fp16 на CPU, QLoRA без CUDA;
- **фичи**: flash-attn, Liger, torch.compile без компилятора, ORPO + packing;
- **данные**: средняя длина диалогов при packing (хватит ли на окно).

Результат — список с уровнями: ошибка / предупреждение / ок. **При ошибках
кнопка «Начать обучение» не запускает процесс**, а показывает, что исправить.
Если настройки изменились, перед запуском проверка выполняется заново.

## Дизайн: редакционный Material 3

Один главный приём — крупная левосторонняя типографика; всё остальное ей подчинено.

- `src/theme.rs` — палитра M3, но формы не «пластиковые»: плоские тональные
  секции без обводки, поля ввода на нижней линии, волосяные разделители.
  Радиусы разные по роли: 28 у диалогов, 10 у filled/tonal-кнопок, 4 у полей,
  чипов и контекстного меню, 0 у текстовых кнопок.
- `src/gui.rs` — своя верхняя панель без рамки Windows: марка «LOCAL FORGE»
  моно-капсом, экран через слэш. Навигация без пилюль: активный пункт —
  вертикальная акцентная черта. Заголовки экранов: mono-overline + 36 px +
  волосяная линия.
- Чат — главный экран: в пустом состоянии крупный блок 54 px «Локальный
  интеллект. Без облака.» слева, акцентная строка, линия и моно-метаданные
  модели. Композер — плоская панель, кнопка отправки — прямоугольник со
  скруглением 10, а не круг.
- Асимметрия намеренная: контент сдвинут влево, метаданные — Roboto Mono,
  ничто не центрируется без необходимости. Диалоги (параметры, выбор папки)
  центрируются как модальные окна.
- Шрифты: Roboto Regular/Medium/Bold и Roboto Mono встроены в exe
  (`assets/fonts/`), поэтому вид одинаков на любой системе. Иконки —
  Material Symbols Rounded (подмножество 4 КБ, только нужные глифы), а не
  самодельные штрихи.

## Команды

```bash
local-forge doctor                    # железо + автоплан
local-forge run                       # окно настроек, затем обучение
local-forge run --start               # сразу начать обучение
local-forge checkpoints --out output_model
```

Ключи `run`:

| ключ | смысл |
|---|---|
| `--model`, `--data`, `--out` | модель, датасет, папка сохранения |
| `--preset` | `game` / `work` / `max` / `turbo` |
| `--max-samples`, `--max-length`, `--batch-size`, `--grad-accum` | как в main.py |
| `--lora-r`, `--lora-alpha` | параметры LoRA |
| `--group-by-length`, `--packing` | режимы padding |
| `--kd`, `--kd-weight`, `--kd-top-k` | дистилляция: KL по top-k шансам учителя (нужен датасет с полем `soft`) |
| `--start` | не показывать экран настроек |
| `--tab chat\|agent\|train\|download\|settings` | с какой вкладки открыть |
| `--theme light\|dark` | тема оформления |
| `--plain` | без окна: транслировать вывод в терминал |
| `--tui` | старый терминальный дашборд |
| `--project`, `--engine`, `--python` | рабочие пути и интерпретатор |
| `-- ...` | любые другие аргументы main.py как есть |

Если окно открыть нельзя (SSH/нет дисплея), приложение само переключается
на терминальный режим.

### Дистилляция KD

Для датасета от `distill/run_distill.py` бери `train_distill.kd.jsonl.gz`:
в каждой строке лежит обычный диалог плюс `soft` — top-k шансы учителя.
Включи в «Данные и режимы» галочку **«Дистилляция KD»**, задай вес KL
(по умолчанию 0.5) и top-k (8). Packing в этом режиме отключается
автоматически: soft-targets привязаны к позициям токенов.

Тренер переводит токены учителя в первый токен ученика, нормирует top-k
и добавляет `KL(teacher || student)` к обычному CE. Работает поверх LoRA,
LISA, AMP и CPU-обучения; в логе появляется `KD: ...`.

Важно про контекст: reasoning учителя часто длиннее `max_length`. В KD-режиме
датасет сначала выбрасывает `<think>...</think>` и оставляет финальный ответ,
а если и ответ не влезает — пропускает сэмпл (с предупреждением), чтобы не
учиться на обрезке. Для длинных ответов подними «Контекст» до 1024–2048 или
генерируй датасет с `--max-answer-tokens`. System prompt в distill-данных
совпадает с промптом чата Local Forge.

## Управление во время обучения

| элемент | действие |
|---|---|
| game / work / max / turbo | профиль нагрузки на лету (потоки — в пределах физических ядер) |
| Пауза / Продолжить | пауза и возврат |
| Сохранить | чекпоинт сейчас |
| Стоп | корректно остановить и сохранить |

В терминальном режиме (`--tui`) те же действия на клавишах: `1–4`, `p`, `s`,
`t`, `x`/`q`, `Ctrl+C`.

## Как это устроено

1. Приложение собирает команду `python python/main.py ...` и запускает её
   дочерним процессом в рабочей папке (`PYTHONUNBUFFERED=1`, чтобы вывод
   не копился блоками).
2. Два потока читают stdout/stderr; парсер достаёт шаг, loss, LR, RAM, эпоху,
